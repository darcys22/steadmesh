Documentation

Steadmesh runs a persistent organisation of AI agents on Kubernetes. You declare it in Terraform, and people reach it through their own representative in Slack or a terminal.

What Steadmesh is and what it needs

You describe an organisation in an infrastructure repository: its culture, teams, seats, harnesses, memory, tools, communication routes and external connections. Running terraform apply provisions it on Kubernetes. When the apply reports ready, each person can message their own representative. The representative keeps persistent context, delegates to other seats through the routes you declared, and reports back. Work items the agents create can be mirrored to a tracker such as Linear, but the organisation does not depend on it.

To run it you need a Kubernetes cluster whose CNI enforces NetworkPolicy, a default StorageClass, Terraform 1.5 or later and kubectl. For real work you also need credentials for the model providers your seats use, and a Slack app or terminal access for the people who talk to it. Model usage is billed by your provider.

Choose a route

Quickstart →Clone the example organisation, apply two Terraform stages and chat with your representative from the terminal. Slack is optional. Run from source →Build the repository and run everything on a local kind cluster with deterministic fakes. No accounts needed. Tutorial →Build an organisation declaration step by step and follow a request end to end. Connect real services →Slack, Linear and the model connections for Claude Code, Codex and Pi. Configuration reference →Every field, default and validation rule. FAQ →Plain-English answers on setup, models, chat, memory, GitHub, data and teardown.

How it fits together

Terraform is the desired-state interface. The controller keeps running after Terraform exits: it wakes sleeping seats when messages arrive, stops idle ones, recovers crashed ones and reports readiness. Seats act on external services by calling tools on the platform service, which checks each call against the grants you declared, and they reach models through the platform's model proxy, which holds the provider credentials.

That is not the whole credential story. With GitHub sandbox delivery, a seat deliberately receives a GitHub credential it can read and use with git and gh, and browser sessions deliver stored session state into the sandbox. Secrets that Terraform creates can also be present in that stage's state. See where API keys go and GitHub and the sandbox.

Core concepts

ConceptWhat it means
OrganisationOne steadmesh_organization resource, which becomes one AgentOrganization object in its own namespace.
SeatA continuing agent identity with durable state: a workspace volume, memory, conversation history and an inbox. Starting a process activates a seat. Replacing its container does not create a new colleague.
RepresentativeA seat bound to one human through a channel binding. Normal human input goes through representatives, and each has a private conversation history. See what the representative does.
Team and templateA team groups seats and gives them shared instructions and resources. Templates are reusable; for example, engineering extends base. Membership is declared on the seat.
InstructionsCulture, team and role guidance, stored as content-addressed bundles. They are applied in order: organisation, then teams, then role, then seat. Instructions shape behaviour but never grant permissions.
HarnessThe agent program that runs inside a seat: claude-code, codex, pi, or the deterministic fake used in tests. A harness is not a model: each seat's harness profile also names a model connection. A seat's harness can be changed without losing its identity or memory. See Harnesses and models.
Memory storeA searchable, revisioned record store scoped as personal, team or organisation. Agents decide what to write; the platform enforces who can read what.
Connection and grantA connection describes an external service (Slack, Linear, GitHub, a model API) by reference. A grant lets a seat or team perform specific operations on a connection, memory store or workspace.
Message routeWhich seats may message which other seats, and whether replies are allowed.
RunA recorded execution of a seat handling a delivered message. See what a run is.

What the platform does not decide

The platform provides participants, context, execution environments and capabilities. It does not impose a CEO, a project owner, an approval chain or a definition of "done". The agents decide how projects are formed, coordinated, reviewed and completed, guided by their instructions. Projects and tasks are business records in the organisation's work items or your tracker, never Terraform resources.

Status

As of 8 October 2026, release v0.5.0. The full flow from apply to conversation passes end to end on a local kind cluster with deterministic fakes. The mixed-harness demo has a recorded run with real model endpoints for Claude Code, Codex and Pi seats and a real GitHub repository; Slack and Linear were fakes in that run, and its key-rotation step was skipped. Per-scenario evidence is on Acceptance status and Demo results.
