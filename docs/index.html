The team stays. Processes can change.

  1. Declare the organisation. Terraform specifies the seats, their roles, memory, message routes, harness profiles and grants. The provider validates the declaration and waits until the organisation is ready.
  2. Keep the seats running. A Kubernetes controller manages each seat's lifecycle. A seat keeps its identity, workspace and stored memory when its process stops, sleeps or is replaced, within the documented retention rules.
  3. Send work through a representative. A person talks to their representative. The team coordinates through the routes and tools you granted, and decides for itself how the work gets done.

Current status and limits

Steadmesh is an early-stage project; the current release is v0.5.0. The mixed-harness demo has a recorded run with real model endpoints and a real GitHub repository, with Slack and Linear as fakes. The acceptance page tracks what is proven, partial and still pending. Review the deployment and security requirements before connecting real services: in particular, a sandbox-delivered GitHub credential is readable inside the seat, and Terraform state can contain the secrets the quickstart creates.

Common questions

Do I need Kubernetes?

Yes. Every documented deployment runs on Kubernetes, including the local route, which uses kind. Install the platform first, then declare the organisation in a second Terraform stage.

Why there are two stages · Quickstart

Is Pi the model?

No. Pi is an agent harness, like Claude Code and Codex. You choose a compatible model endpoint for each seat and supply that provider's credentials. Each harness supports different model APIs.

Where the Pi key goes · Which model it uses · Harness matrix

What persists between messages?

Each seat has durable memory stores, message history and a workspace volume, and supported harnesses can resume their native session. Compaction summarises old context rather than recalling it perfectly, and losing the storage loses what was on it.

Context between messages · Where data is stored

Can agents read my credentials?

Model credentials stay with the platform's model proxy. But GitHub sandbox delivery deliberately gives the seat a credential it can read, and a personal access token keeps whatever scope it has at GitHub. Terraform state can also contain secrets that Terraform creates.

Where API keys go · GitHub and the sandbox

What happens when I stop or delete it?

Idle stopping, retiring a seat, deleting the organisation and deleting the cluster are different actions. Retention can keep data when an organisation is deleted, but deleting the namespace, database or cluster can remove it. Retention is not a backup.
