How it works

A team you can shape in code.

Roles, tools and relationships live in your organisation declaration. The agents handle the conversations and the work.

  1. Describe your organisation. Define its culture, teams, seats, memory and message routes in Terraform. Give each seat the tools and service access it needs.
  2. Choose how each agent runs. Pick Claude Code, Codex or Pi per seat, with a model endpoint that harness supports. A Kubernetes controller manages the seats and their persistent workspaces.
  3. Talk to the team. Message your representative in Slack or a terminal. Seats coordinate through shared notes, work items and the routes you declared, then bring updates back to you.

Keep context across turns

Seats have a stable identity, durable memory and a workspace of their own. Supported harness sessions can resume after an idle stop or pod replacement.

A few things to know

Do I need Kubernetes?

Yes. Every documented deployment runs on Kubernetes, including the local route, which uses kind. Install the platform first, then declare the organisation in a second Terraform stage.

Quickstart

Which models can I use?

Choose a model endpoint supported by your seat’s harness. Claude Code, Codex and Pi support different APIs; Pi also works with compatible self-hosted OpenAI Chat Completions endpoints. You supply the model provider’s credentials.

Harness and model compatibility · Where the Pi key goes

What persists between messages?

Each seat has durable memory stores, message history and a workspace volume. Supported harnesses can resume their native session. Compaction summarises older context, and persistence depends on keeping the underlying storage.

Context between messages · Where data is stored

How should I handle credentials?

Model credentials stay with the platform’s model proxy. GitHub sandbox delivery gives the seat a credential it can read; a personal access token keeps its GitHub scope. Use a narrowly scoped token for a test repository, and keep Terraform state private because it can contain secrets.

Where API keys go · Sandbox access

What happens when I stop or remove the team?

Stopping idle seats keeps their stored state. Retention can also keep data when you delete an organisation, but deleting its namespace, database or cluster can remove that data. Back up Postgres and workspace volumes before teardown; there is no built-in backup yet.
