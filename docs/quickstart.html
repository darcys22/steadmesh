Quickstart

Install Steadmesh into your Kubernetes cluster from a published release, declare a small organisation, and talk to your representative in Slack. No clone needed.

Terraform downloads everything:

  • the darcys22/steadmesh provider from the Terraform Registry;
  • the platform chart and images from ghcr.io/darcys22/steadmesh;
  • the modules from GitHub.

You get one personal representative per person, plus an engineering lead and an engineer that representatives can delegate to. Agents run Claude Code.

Optional: a Linear API key and team IDLets agents create projects and issues.

Install

  1. Get the quickstart. This copies two small Terraform roots into a new directory. platform/ installs Steadmesh, and organisation/ declares your agents. They are separate stages because the organisation's provider needs the platform's CRDs to exist before it can plan.

    mkdir steadmesh && cd steadmesh
terraform init -from-module="github.com/darcys22/steadmesh//quickstart?ref=v0.1.0"

  2. Install the platform. Set kube_context and your tokens in terraform.tfvars.

    cd platform
cp terraform.tfvars.example terraform.tfvars
terraform init
terraform apply

    This creates:

    • the steadmesh-system and steadmesh namespaces;
    • Postgres;
    • the platform chart, which holds the CRDs, the controller and the platform service;
    • the credential Secrets.

    Terraform only ever uses the context you name, never your current one. The tokens are stored in this stage's Terraform state, so keep the state private.

  3. Declare your organisation. Set your Slack workspace ID and the people who get a representative.

    cd ../organisation
cp terraform.tfvars.example terraform.tfvars
terraform init
terraform apply

    This stage reads the cluster, namespace, images and secret references from the platform stage's state. terraform apply returns once every seat has passed its readiness checks. The first time, that takes a few minutes while the seat images are pulled. If a check fails, the error names the condition. See Checking readiness.

  4. Talk to your representative. In Slack, open the app and send it a direct message. Your representative replies in the same DM. Try:

    • asking it to remember a preference;
    • asking it to have engineering look into something;
    • with Linear connected, asking for a project for a small task.

Watch the agents work

Set enable_console = true in platform/terraform.tfvars and apply that stage. Then open the read-only console:

kubectl --context <your-context> -n steadmesh-system port-forward deploy/steadmesh-console 8090
# then browse to http://127.0.0.1:8090

Shape your organisation

Everything about your organisation lives in organisation/:

To changeEdit
How everyone worksinstructions/culture.md
How representatives behaveinstructions/representative.md
Who has a representativehumans in terraform.tfvars. One Slack app serves them all.
The teamlocal.engineering in main.tf, for example reviewer = { role = "reviewer", display_name = "Reviewer" }. Then add a route under message_routes: seats can only message along declared routes.
What agents may dogrants: a connection is usable only through a grant.

terraform plan lists the seats each change affects. Seats keep their identity, workspace and memory across applies. The tutorial explains every part of the declaration.

Upgrade or remove

  • Upgrade: in your copy, change every ?ref=v…, steadmesh_version and the darcys22/steadmesh provider version to the new release. Apply platform/, then organisation/.
  • Remove: run terraform destroy in organisation/, then in platform/. Destroying the platform deletes its namespaces, and with them the database.
