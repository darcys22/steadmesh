# Steadmesh Provider

[Steadmesh](https://github.com/darcys22/steadmesh) turns an organisation declared in Terraform into persistent agents on Kubernetes. People message their personal representative over Slack. Representatives delegate to other seats, such as an engineering lead or an engineer, over routes you declare, and agents act on external services, such as Linear, only through grants you declare.

The provider has one resource, [`steadmesh_organization`](https://registry.terraform.io/providers/darcys22/steadmesh/latest/docs/resources/organization), which writes the organisation to the cluster and, by default, waits until it is ready to work.

## Before you start

The cluster must already run the Steadmesh platform: its CRDs, controller and platform service. The provider checks that the CRDs exist when it is configured, so install the platform in a separate Terraform root and apply it first. The [quickstart](https://github.com/darcys22/steadmesh/tree/main/quickstart) does this in two stages:

```sh
terraform init -from-module=github.com/darcys22/steadmesh//quickstart?ref=v0.2.0
```

## Example Usage

```terraform
terraform {
  required_providers {
    steadmesh = {
      source  = "darcys22/steadmesh"
      version = "~> 0.2.0"
    }
  }
}

provider "steadmesh" {
  kubeconfig_path = "~/.kube/config"
  kube_context    = "my-cluster" # always explicit: the current context is never used
  namespace       = "acme-org"   # the organisation namespace
}
```

The provider talks to the Kubernetes API with your kubeconfig. `kube_context` is required, so a plan never runs against whichever cluster happens to be current. Credentials for Slack, Anthropic and Linear are never passed to the provider. Connections refer to Kubernetes Secrets or Vault paths that the platform reads at runtime, so secret values never appear in plans or state.
